# 2026.309.1841 — fix(bed): derive the lease user's home from passwd

## Summary

The `check-pod-crabbox-systemd-init` R10 bed reset and asserted the lease user's SSH directory at a hardcoded `/home/crabbox`. The lease contract in `opencharly/pod-crabbox` adopts the image's uid 1000 account with `usermod -l crabbox -s /bin/bash`, which renames the login but does **not** change the passwd home field: `getent passwd crabbox` reports `/home/user`. The reset therefore removed nothing, and `test ! -e /home/crabbox/.ssh/authorized_keys` was vacuously true.

This derives the home from the passwd entry once, at the top of the absence step, asserts it is non-empty so a missing user fails loudly instead of silently reverting to a vacuous check, and uses `"$home/.ssh"` for both the reset and the assertion. The derivation is the same one the contract's own `candy/crabbox-guest/bootstrap.sh` uses (`HOME_DIR=$(getent passwd "$USER_NAME" | cut -d: -f6)`) and the same form already used by the `pod-crabbox-code` bed, so there is no second idiom.

This is one of three sibling PRs fixing the same defect in the three lease beds — `opencharly/pod-crabbox`, `opencharly/pod-crabbox-systemd` and `opencharly/pod-crabbox-nested`. It references `opencharly/pod-crabbox#5` and does not close it; the issue stays open until all three merge.

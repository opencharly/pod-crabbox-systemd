**The image.** `charly.yml` imports the base at a pinned tag and sets the OCI entrypoint:

```yaml
import:

    - cachyos: '@github.com/opencharly/distro-cachyos:v2026.300.1129'   # the tag the base imports

    - crabbox: '@github.com/opencharly/pod-crabbox:v2026.307.1828'      # newest base tag
pod-crabbox-systemd:
    candy:
        base: crabbox.pod-crabbox
        user: root            # systemd refuses a non-root PID 1
        uid: 0
        gid: 0
        entrypoint: [/sbin/init]
        candy: [systemd-init]
```

`candy/systemd-init/` is the delta: `sshd.service` and `crabbox-bootstrap.service` enabled
via `multi-user.target.wants` symlinks, `serial-getty@hvc0.service` masked to `/dev/null`,
`/etc/sysctl.d/50-pid-max.conf` (`kernel.pid_max=32768`),
`/usr/lib/systemd/system-shutdown/krun-poweroff` (`systemctl reboot -ff` on
poweroff/halt), and the runner's .NET deps `icu krb5 libunwind lttng-ust`.

**The image tag is the git tag.** The box is named after the repo, and the copied
`.github/workflows/image.yml` passes the newest `v*` tag minus its `v` to
`charly box build --tag`, which uses the supplied tag verbatim.

### The two non-blocking notes

- **`defaults.tag: auto`.** Measured: the CI caller always passes the newest git tag, and
  `charly box generate pod-crabbox-systemd --tag ci-test123` uses it verbatim for the image
  and its imported base (`ARG BASE_IMAGE=ghcr.io/opencharly/pod-crabbox:ci-test123`). `auto`
  is only the LOCAL-build fallback (the local builds above are clock-tagged
  `2026.308.1904`). `AGENTS.md` now says exactly that. The published image tag is always the
  git tag.
- **The reusable is called at `@main`.** That line is copied verbatim from
  `pod-crabbox`'s own caller (identical blob), and the reusable's header documents `@main`
  as its consumption ref. Pinning it here alone would make this repo's caller diverge from
  the producer's, which is the opposite of the W5.2 consistency rule; a pin is an org-wide
  change to every caller, not a per-repo fork.

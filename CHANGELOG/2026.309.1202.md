# 2026.309.1202 — feat(bed): add the disposable systemd-init lease bed

## Summary

**Head `fdaea87df7e905e3fdb22809a894e1b508de4bac` — 1 file, +171/−0.** Adds `check-pod-crabbox-systemd-init`, the second `pod-crabbox*` disposable R10 bed and the first for the systemd-init variant.

The base repo's `check-pod-crabbox-lease` bed proves the `/crabbox` contract on the DIRECT-mode image (`exec sshd -D`). A direct-mode bed cannot see a unit that failed to start, a unit that was never enabled, or an image that boots something other than systemd, so the variant's behavioural contract — systemd as PID 1, the unit set enabled, and the lease contract on TOP of systemd — was unproven. This commit adds the bed that proves it, in the base bed's three-step shape:

1. **ABSENCE** — reset the state, assert PID 1 is systemd, then prove the freshly generated key is refused and no `authorized_keys` exist. The refusal must be an authentication refusal; a venue that does not answer fails the step, so a broken endpoint cannot read as "nothing applied yet".
2. **PERFORM** — write `authorized_keys`, `lease.env` and `bootstrap.sh` temp + `mv` (the contract's own input protocol), then `systemctl restart crabbox-bootstrap.service`, so the UNIT — not a hand-run copy of the script — consumes them.
3. **PRESENCE** — PID 1 is systemd, `sshd.service` and `crabbox-bootstrap.service` are enabled and active, and over the contract's own SSH path as `crabbox`: the key is accepted, `sudo -n true` succeeds, and `/usr/local/libexec/crabbox/ready` exits 0.

The plan runs at every check-live pass, including the fresh-rebuild pass: step 1 resets and step 2 re-applies, so each pass measures its OWN perform.

**The containerd substrate leg is NOT claimed.** The bed authors no `engine:` selector and runs on the pod substrate only; the pinned toolchain's engine-selector gap is opencharly/charly#1109.
